## Cross-cutting rules
- **ADR-013 / BR40** (no clinical data in identity): token claim allowlist `accessTokenClaims`; `forbiddenClaims` list; test asserts no unexpected claim in access/ID tokens (`flow.test.ts`).
- **KX-10 identity row** (refresh rotation, revoke, OTP rate limits - Kiorex Account parity): covered by KA-02/04/05 above.
- **No custom crypto in production**: dev IdP = `oidc-provider` (certified), `jose`, `@simplewebauthn/server`; `crypto` only for CSPRNG codes, salted HMAC of OTPs, constant-time compare and the audit hash chain. Production uses a managed IdP; `apps/dev-idp` refuses to start when `NODE_ENV=production`.
- **New token claims (additive, none clinical)**: `acr`, `amr`, `auth_time` (KA-10); `kx_orgs` only with scope `kx_org` (KA-09); `act` on guardian tokens (KA-06). All are in `accessTokenClaims`; `ka06`/`ka09`/`ka10` tests assert the allow-list and `forbiddenClaims` for every token type.
- **Messaging is mocked** (CLAUDE.md founder decision): OTP/invitation/notification messages go to the log and the DB dev inbox `GET /dev/inbox` (`src/notify.ts`, `dev-inbox.test.ts`). Real WhatsApp/SMS wiring = NEEDS_HUMAN provider go-live.
- **No tax-authority reporting**: `test/no-tax-authority.node.test.ts` fails if source/config/infra references ETA / e-invoice / e-receipt / ZATCA submission.
- **Events** `guardian.link.changed`, `membership.changed`, `account.merged` are defined additively in `kiorex-contracts` 1.2.0 and conformance-checked by `events-contract.test.ts` (skipped when the sibling repo is absent). Dev transport = `event_outbox` + `GET /dev/events`; production delivery transport (back-channel-style push vs. polling) is an open integration decision.
- **ADR-023/025**: `account.passkeys` and `account.provider_sso` are flags (capabilities, ship ON); OTP rate limits/lockout are safety controls, never flags.
